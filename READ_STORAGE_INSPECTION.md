# Internal whole-storage inspection

The additive UniFFI/TypeScript inspector is an observation API, not a physical owner marker, migration, initializer, or app activation. Matching rebuilt binaries remain required. Its result distinguishes unselected pristine metadata from selected occupancy. Missing journal state never implies physical emptiness. Application marker contents and permission to create a fresh journal remain application policy.

`sync_storage_inspection::inspect_storage` accepts bounded ASCII namespace/database names (64bytes, letters/digits/underscore/hyphen; bound or compared only, never interpolated as SQL), existing native journal options, and at most16 distinct compiled application-table identifiers (64ASCII bytes each, no reserved `_sync_` prefix). Selected metadata must contain exactly the expected namespace/database, only the eight fixed journal tables, two bootstrap tables and configured application tables, and no unsupported durable metadata. Every native row must belong to the expected structured key; component owner columns and suffixes are checked before payload loading. Existing state and bootstrap codecs then validate the expected journal. Orphans, aliases, dual/third keys, unsupported versions, partial bootstrap schema and malformed state fail closed. Terminal bootstrap headers can retain older authorization than the current checkpoint; their own original context is validated rather than equated to the newer journal authorization.

Results contain only Missing/Present journal counts/barrier and configured application-table schema/row booleans, or PristineUnselected. They contain no foreign IDs, definitions, ACLs or payloads. No counters, native schemas, markers, journal revisions or session generation are written. Session selection itself creates NS/DB metadata, so an unmarked selected store after a crash must be preserved as unknown by the app.

Inspection holds the database journal-lifecycle WRITE guard without incrementing session generation. It checks closed/session/sticky database poison before waiting, after acquisition, after phase awaits and before returning. Existing workers on other keys therefore cannot mutate concurrently. Unsettled worker drop, CommitUnknown or RollbackFailed poison is not repaired by reading disk. Tests setting poison prove inspector response to the flag; existing cancellation tests independently prove its actual origins. Raw private-table SQL/session misuse remains outside this native ownership contract.

ROOT metadata exception: pinned3.2.4 scalar ROOT projections and LET require a selected namespace even though direct INFO FOR ROOT works unselected. The inspector therefore performs one direct typed INFO FOR ROOT with a2second read timeout, then checks borrowed metadata cardinality/default fields before copying any name/output. The engine has already allocated this metadata Value. This is postdecode admission, NOT a predecode, engine-scan, CPU or RSS bound. No definitions/ACLs are logged or bridged. Only operational nodes/system fields are excluded from durable ownership decisions. Nondefault root config/defaults/accesses/users fail closed.

Selected namespace/database metadata uses scalar admission first. Table count is bounded by10native+16application tables and names by64bytes before names are fetched. Reusable internal state/bootstrap readers consume these admitted names, avoiding another full schema-definition fetch on this new path. Existing exact-key component/blob/aggregate limits are unchanged. LIMIT1 predicates bound returned witnesses, not physical scan work. Application occupancy uses fixed compiled names, never arbitrary caller SQL.

Selected data reads use one explicitly cancelled transaction. Cancellation failure is returned as a redacted persistence error; the API does not promise confirmed cancellation on that error. ROOT/namespace/schema metadata reads precede the transaction under the same lifecycle WRITE guard because an unselected transaction cannot start. The result releases the guard and is only an observation, not a future-write lease. A fresh app adapter must keep its connection private and retain its own current-owner/quiescence fence through marker validation and catalog publication.

Host test command (default profiles, no RUSTFLAGS): `cargo +1.96.1 test -p surrealdb-rn-core --lib`. The SurrealKV reopen inspector test is intentionally explicit: set STORAGE_INSPECTION_FIXTURE to a fresh owned persistent path and run the ignored `surrealkv_reopen_preserves_occupancy_and_never_creates_tables` test. Preserve fixture files after evidence collection. Host tests do not establish rebuilt mobile/device acceptance. No automatic physical deletion or occupied-journal rekeying is authorized by this module.

## Additive bridge surface

Rust exports `inspect_storage(Arc<SurrealDatabase>, NativeStorageInspectionOptions)` with typed result and fixed redacted NativeStorageInspectionError variants. `SurrealClient.inspectExperimentalStorage(options, callOptions)` snapshots own data properties, validates normal JS inputs before dispatch, and freezes copied bounded output. Accessors/proxies, malformed output and native failures yield fixed error classifications with no raw messages, identities or cause. Native limits remain authoritative; UniFFI input allocations occur before Rust validation. AbortSignal withdraws this read observation, never performs cleanup or mutates ownership.

Generated TS/C++ and TurboModule entries must come from the same exact host Rust metadata and reproduce byte-for-byte across generation runs; existing exported checksums must remain unchanged and new inspectStorage checksum must match the actual host symbol. A whole old native binary can fail the existing generated import initialization before the typed facade runs; method-level UnsupportedAbi applies after module initialization. Native fingerprints and matching rebuilt iOS/Android binaries/device tests remain activation gates. Host checksum matching is not mobile method execution or release acceptance. No package publication or application activation is included.
