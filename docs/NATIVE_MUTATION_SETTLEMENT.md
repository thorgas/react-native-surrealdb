# Native mutation settlement

Public native mutations acquire cancellable per-runtime admission before spawning one owned Tokio worker. The worker retains the client, admission permit, database lifecycle read guard and runtime mutex through storage completion and runtime/read-journal publication. Cancelling the caller or freeing the UniFFI future drops only its join waiter. Waiting callers create no workers. Close withdraws a handle immediately and physical database close waits for lifecycle readers.

The inventory includes initial schema/state creation, enqueue, push/pull installation, conflict resolution, subscription start/cancel/response, durable scope barriers, and bootstrap begin/page/cancel/complete. Bootstrap bind/progress only read storage and retain ordinary lifecycle/runtime access.

A guard dropped while a mutation may be dispatched poisons the entire physical database wrapper lifetime. Returned CommitUnknown or RollbackFailed also poison it: awaiting a failed channel does not prove database settlement. Poison survives sync-wrapper destruction and namespace/database session generation changes. Explicit sync open cannot clear it. Reuse requires proven router/engine retirement, normally a fresh process; no automated retirement protocol is claimed. Known rollback/revision failures retain their existing handling. Schema installation uses a direct multi-statement query, so any returned database error there conservatively poisons the lifetime as well; deterministic validation failures before sending remain ordinary input errors. Inspectors reject poison before and after awaited storage inspection. Closing/reconnecting a wrapper or merely incrementing its session generation does not demonstrate router retirement.

Tests exercise caller abort and actual pinned UniFFI RustFuture cancel/complete/free at the postcommit publication pause. This is host FFI-core proof, not a generated argument-lifting or mobile JavaScript test. The per-store test-only persistence pause separately tests (a) an ACK withheld after successful commit, and (b) commit first polled to Pending after dispatch, with the worker retaining the commit future until its result. The latter does not claim an independently delayed, still-uncommitted server transaction; it establishes dispatch ownership and prevents a sibling reopening before settlement/publication. All fault state is instance-local and absent from production builds.

No async Drop, new dependency, wire protocol or persistence format change is introduced. Arc receivers retain existing method parameters; matching generated binding checks are still required before integration.
